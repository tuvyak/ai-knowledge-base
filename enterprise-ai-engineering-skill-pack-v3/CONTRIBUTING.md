# Contributing

## Rules

- Preserve the normalized skill template.
- Use concise, imperative bullets.
- Avoid duplicating shared principles unless the skill requires a specialized rule.
- Add requirements only when they change model behavior.
- Keep examples only when they prevent likely ambiguity.
- Use `TBD` for unknown values.
- Separate FACT, ASSUMPTION, DECISION, and RISK.
- Update `CHANGELOG.md` for material changes.
- Use semantic versioning.

## Review

- Confirm the skill remains self-contained.
- Confirm the change reduces ambiguity.
- Confirm no material control was removed.
- Estimate token impact before merging.
